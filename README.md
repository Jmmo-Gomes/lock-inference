# Lock Inference — Formal Specification and Verification (Cameleer / Why3)

## Overview

This repository contains an OCaml implementation of a **lock inference algorithm** for resource‑centric concurrency control.

⚠️ **Important authorship note**

- All core algorithmic logic was originally implemented by **Pedro Salgado**.
- **My contribution**, presented in the associated **thesis**, consists **exclusively of formal specifications and verification work**.

No algorithmic behavior was changed or reimplemented.  
All modifications are **specification‑oriented** and intended to enable and analyse formal verification.

To fully understand the design decisions, correctness properties, and verification methodology, **the thesis PDF must be read in full**.

---

## Repository structure

- `lib/`  
  Core OCaml modules implementing the lock inference pipeline (original implementation).

- `bin/`  
  Entry point executable (`main.exe`).

- `OUnit/` (or `test/`)  
  Unit tests using **OUnit2**.

- `Figures/`  
  Images used in the thesis and documentation:
  - Specification coverage by module/function
  - Cameleer / Why3 verification condition status

## Setup

### Prerequisites

Install the following:

- **OCaml** (via opam)
- **dune**
- **cameleer**
- **why3**
- At least one SMT solver (e.g. **Alt‑Ergo**, **Z3**, **CVC4**)
- **OUnit2**

### Recommended OCaml switch

```bash
eval $(opam env --switch=5.1.0)
```

---

## Build and execution

### Build the project

```bash
dune build
```

### Run the main executable

```bash
dune exec bin/main.exe fich.txt
```

Replace `fich.txt` with the desired input file.

---

## Running Cameleer (formal verification)

From the `lib/` directory (or by explicitly adding it to the load path):

```bash
cameleer -L . lockInference.ml
```

This generates verification conditions (VCs) and opens them in **Why3**.

Inside the Why3 interface, SMT provers can be run on each VC
(depending on configuration, often using key `3`).

---

## Running tests

From the test directory (or repository root, depending on dune configuration):

```bash
dune build ./<test_file>.ml
dune exec ./<test_file>.exe
```

The console output reports test results.

## What was done in this work

This work focuses **exclusively on formal specification and verification**.

### Contributions

- **Formal specifications**
  - Preconditions, postconditions, and invariants were written using Cameleer
  - Specifications capture correctness properties of the existing implementation

- **Verification‑driven adjustments**
  - Minor structural refactorings were applied *only when necessary* to allow verification

- **Verification coverage analysis**
  - Functions were classified as:
    - Fully specified and verified
    - Partially specified / pending verification
    - Not yet specified

All proofs, assumptions, and limitations are discussed in detail in the thesis.
